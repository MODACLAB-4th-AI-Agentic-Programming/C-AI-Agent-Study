3 · ARCHITECTURE

리뷰가 만들어낸 아키텍처 개선

Claude/Gemini가 잡아낸 진짜 이슈들 — 리뷰가 단순한 코드 스타일 검사가 아니었다는 증거.

PR #6 · M-2 · MAJOR
Race Condition · 중복 지원 차단

단순 add()는 동시 두 번 탭 시 두 번 등록. 결정적 doc ID + runTransaction으로 원자적 차단.

// before — 비결정적, 동시 등록 가능 await applicationsCol.add({...}); // after — 결정적 ID + 트랜잭션 final docId = '${userId}_${jobId}'; await firestore.runTransaction((tx) async { final snap = await tx.get(ref); if (snap.exists) throw AlreadyApplied(); tx.set(ref, payload); });
PR #6 · B-1 · BLOCKER
자동 저장 → 명시적 사전 체크

폼 진입만으로 지원이 등록되던 버그. hasApplied()를 분리해 "체크"와 "제출"을 다른 함수로.

// before — 진입 시점에 부작용 _checkAlreadyApplied() async { await repo.submit(payload); // 😱 } // after — 순수 read-only 체크 final already = await repo.hasApplied(userId, jobId); if (already) showAlreadyApplied();
PR #4 · B-1
시급/일급 표기 통합

시급 12,000을 "1.2만원"으로 잘못 표기하던 버그. JobModel.formattedSalary getter로 6곳 중복 제거 + 분기 일원화.

PR #4 · M-2
JobFilter.copyWith null 표현

기존 copyWith는 "값 없음"과 "null로 설정"을 구분 못 함. sentinel 패턴 도입으로 명시적 unset 가능.

# 6-stage pipeline · zero-warning enforced $ bash tools/verify_local.sh [1/6] flutter pub get [2/6] dart format --set-exit-if-changed [3/6] flutter analyze # 0 warnings [4/6] flutter test # 51/51 passing [5/6] graphify update . # AST refresh [6/6] pages build check # wiki sync
