URL 처리

http 없이 입력하면 https://를 자동으로 붙입니다. 이후 YouTube URL 정규식으로 비YouTube URL인지 확인하고, 맞지 않으면 경고만 출력하고 계속 진행합니다.

macOS 권한 확인

실제 녹화 전에 화면 기록 권한이 있는지 확인합니다. 권한이 없으면 시스템 설정 → 개인정보 보호 → 화면 기록에서 Terminal을 추가하라는 안내를 출력합니다.

주요 옵션들

--recorder ffmpeg / quicktime 선택
--browser chrome / firefox 선택 (기본: chrome)
--duration N N초 후 자동 종료

--region 옵션의 의미

브라우저가 영상 위치를 잘못 잡을 때 사용합니다. --dry-run으로 먼저 좌표를 확인한 뒤 물리 픽셀 좌표를 직접 전달합니다. 브라우저는 여전히 열립니다 — 녹화할 영상을 재생해야 하기 때문입니다.

실행 분기

--region 있음 → 영상 요소 자동 탐지 생략, 사용자 좌표 사용

--region 없음 → 브라우저에서 영상 요소를 찾아 좌표 자동 계산

Python은 브라우저를 직접 제어할 수 없습니다. WebDriver 프로토콜이라는 표준 HTTP API를 통해 Driver 바이너리에 명령을 보냅니다. Chrome은 CDP, Firefox는 Marionette 프로토콜을 사용하지만 Python 코드는 동일합니다.

webdriver-manager

브라우저 버전을 자동으로 감지해 ChromeDriver 또는 GeckoDriver를 다운로드·캐시합니다. Apple Silicon에서는 adhoc 서명 문제로 codesign --sign - 수정이 필요합니다 — setup.sh가 자동 처리합니다.

Chrome vs Firefox 차이점

창 크기 고정

브라우저 종류에 관계없이 1280×1000, 위치 (0, 0)으로 고정합니다. 좌표 계산의 일관성을 보장합니다.

3 / 13  ·  페이지 로드 & 대기 전략

1단계 — 페이지 이동

Python이 ChromeDriver에 URL을 전달하면 ChromeDriver가 CDP를 통해 Chrome에 네비게이션 명령을 전송합니다. Chrome은 실제 HTTP 요청을 보내고 페이지를 로드합니다.

2단계 — body 태그 대기 (최대 10초)

Selenium의 WebDriverWait가 0.5초 간격으로 폴링합니다. body 태그가 DOM에 나타나면 기본 HTML 로드가 완료된 것으로 판단합니다. 10초 안에 나타나지 않으면 타임아웃 예외가 발생합니다.

3단계 — 추가 3초 대기

YouTube처럼 SPA(Single Page App) 구조의 사이트는 body 등장 후에도 JavaScript가 동적으로 영상 플레이어 DOM을 조립합니다. 3초를 더 기다려야 #movie_player가 완성됩니다.

SPA vs 일반 사이트

일반 사이트 — HTML에 영상 태그가 처음부터 있어서 body 로드 직후 탐지 가능합니다.

YouTube(SPA) — React/Polymer 기반으로 JS가 DOM을 동적 생성합니다. ytd-player, #movie_player 같은 커스텀 엘리먼트가 JS 실행 후에야 나타납니다.

왜 폴링인가

WebDriver 프로토콜에는 "특정 요소가 생길 때 알려줘"라는 이벤트 구독 방식이 없습니다. 그래서 Selenium은 일정 간격으로 조건을 반복 확인하는 폴링 방식을 사용합니다.

YouTube는 Web Components 기반입니다. ytd-app, ytd-watch-flexy, ytd-player처럼 ytd- 접두어가 붙은 커스텀 HTML 엘리먼트들이 중첩됩니다. 일반적인 div·span이 아니라 JS로 정의된 독자적인 컴포넌트입니다.

#movie_player — 탐지 대상

6 / 13  ·  DOM Rect 취득 — 3가지 보조값

element.rect — 뷰포트 기준 좌표

Selenium이 CDP를 통해 JS의 getBoundingClientRect()를 실행합니다. 결과는 브라우저 뷰포트 좌상단 기준 CSS 논리 픽셀(px)입니다. Retina 디스플레이에서도 배율이 적용되지 않은 논리 픽셀을 반환합니다.

window.devicePixelRatio — 배율

CSS 논리 픽셀을 물리 픽셀로 변환하는 비율입니다. Retina MacBook은 2.0, 일반 Full HD 모니터는 1.0. JS를 직접 실행해 Chrome에서 가져옵니다.

window.screenX / screenY — 창 위치

Chrome 창의 OS 화면 좌상단 기준 논리 픽셀 위치입니다. --window-position=0,0으로 창을 배치했어도 macOS 메뉴바(37px) 때문에 screenY는 37이 됩니다.

outerHeight − innerHeight — 브라우저 UI 높이

전체 창 높이에서 뷰포트 높이를 빼면 탭바 + 주소창의 높이가 나옵니다. 보통 약 100px. 이 값이 없으면 뷰포트 y 좌표가 화면 어디에 있는지 알 수 없습니다.

녹화

8 / 13  ·  screencapture 프로세스 실행

screencapture -v -R 옵션

-v는 비디오 녹화 모드, -R x,y,w,h는 지정 영역만 캡처하는 옵션입니다. 툴바가 나타나지 않고 즉시 녹화를 시작합니다. 좌표는 논리 픽셀이므로 QuickTimeRecorder에서 물리 픽셀 ÷ scale로 역변환해 전달합니다.

stdin=PIPE — 녹화 지속의 핵심

PIPE를 열지 않으면 screencapture가 stdin의 EOF를 감지해 즉시 종료합니다. PIPE를 열어두면 데이터가 없어도 연결이 유지되어 녹화가 계속됩니다.

별도 프로세스로 실행

Python이 subprocess.Popen으로 screencapture를 백그라운드 프로세스로 실행합니다. Python은 자신의 작업(대기 루프, Ctrl+C 처리)을 계속하면서 screencapture는 독립적으로 녹화합니다.

setpgrp — 프로세스 그룹 격리

터미널에서 Ctrl+C를 누르면 SIGINT가 같은 프로세스 그룹의 모든 프로세스에 전달됩니다. os.setpgrp()로 screencapture를 별도 그룹에 배치하면, Ctrl+C가 record.py에만 전달되고 screencapture는 영향받지 않습니다.

setpgrp 없을 때의 문제

Ctrl+C → SIGINT → screencapture 강제 종료 → 파일 저장 실패. 녹화된 내용이 mp4로 저장되지 않고 사라집니다. setpgrp가 없으면 항상 이 문제가 발생합니다.

stdout/stderr 억제

screencapture의 상태 출력이 터미널을 방해하지 않도록 DEVNULL로 버립니다. record.py의 출력만 표시됩니다.

--duration 지정 시 — 자동 종료

지정한 초 동안 time.sleep(N)으로 블록합니다. N초 후 자동으로 stop()이 호출됩니다. 중간에 Ctrl+C를 눌러도 즉시 종료됩니다.

--duration 없을 때 — 수동 종료

_wait() 메서드가 screencapture 프로세스가 살아있는 동안 0.5초마다 상태를 확인하며 대기합니다. Ctrl+C를 누르거나 screencapture가 먼저 종료되면 루프가 끝납니다.

KeyboardInterrupt 처리

Ctrl+C가 발생하면 Python이 KeyboardInterrupt를 던집니다. try/except로 잡아서 "녹화 종료 신호 수신"을 출력합니다. finally 블록에서 반드시 stop()이 실행되어 screencapture를 정상 종료하고 파일을 저장합니다.

finally 블록의 중요성

stop()이 finally 안에 있기 때문에 Ctrl+C, 일반 종료, 예외 발생 어떤 경우에도 반드시 실행됩니다. 녹화 파일이 저장되지 않는 사고를 방지합니다.

브라우저 종료

record() 완료 후 driver.quit()이 호출됩니다. 이 역시 finally 블록에 있어 예외 상황에도 Chrome 창이 남지 않습니다.

종료

10 / 13  ·  screencapture 종료 메커니즘 상세

왜 SIGINT를 보내지 않는가

screencapture가 setpgrp()으로 별도 그룹에 배치되어 있기 때문에 Python에서 SIGINT를 직접 보내도 응답하지 않습니다. 실제로 테스트해서 동작하지 않음을 확인했습니다.

stdin에 "q" 쓰기 — 정상 종료

screencapture -v는 stdin 키 입력을 받습니다. "q"를 stdin에 쓰면 screencapture가 정상적으로 녹화를 마무리하고 파일을 저장합니다. SIGKILL과 달리 파일이 손상되지 않습니다.

5초 대기 → SIGTERM fallback

"q"를 보낸 후 최대 5초를 기다립니다. 5초 안에 종료되면 정상. 응답 없으면 SIGTERM을 보냅니다. SIGTERM도 파일 저장을 시도하는 "부드러운" 종료 신호입니다.

신호 흐름 요약

Ctrl+C
 → SIGINT → record.py 수신
   → KeyboardInterrupt 발생
     → finally: stop() 호출
       → stdin.write("q")
         → screencapture 정상 종료
           → mp4 파일 저장 완료

screencapture는 SIGINT를 받지 않음

setpgrp으로 격리되어 있으므로 Ctrl+C의 SIGINT가 전달되지 않습니다. record.py가 stop()으로 명시적으로 종료시켜야 합니다. 이 설계 덕분에 파일이 항상 안전하게 저장됩니다.

실제 테스트 결과

5초 녹화 → Ctrl+C → stop() → 5.3MB mp4 파일, exit 0 확인. 파일 손상 없이 정상 저장됩니다.

11 / 13  ·  ffmpeg 레코더 — 기본값 비교

avfoundation 화면 캡처

macOS의 AVFoundation 프레임워크를 통해 화면 전체를 스트리밍 캡처합니다. 인덱스 1이 보통 메인 디스플레이, :none은 오디오 없음을 의미합니다.

-vf crop 필터로 영역 지정

전체 화면을 캡처한 뒤 crop=w:h:x:y 필터로 원하는 영역만 잘라냅니다. 물리 픽셀 좌표를 그대로 사용합니다 (screencapture와 다름).

SIGINT로 종료

ffmpeg은 SIGINT를 받으면 현재까지의 내용을 파일에 저장하고 정상 종료합니다. Python에서 proc.send_signal(SIGINT)로 종료 신호를 보냅니다.

setpgrp 불필요

ffmpeg은 자체적으로 SIGINT를 처리해 파일을 저장합니다. 별도 프로세스 그룹 격리가 필요 없습니다.

출력 파일 경로

기본값은 screen_captures/output.mp4입니다. 디렉토리가 없으면 자동으로 생성합니다. --output 경로로 변경할 수 있습니다. mp4 컨테이너, H.264 코덱으로 저장됩니다.

저장 타이밍

stop()이 완료된 후에야 파일이 완성됩니다. screencapture가 "q"를 받고 내부 버퍼를 플러시해 mp4 헤더·푸터를 쓰는 시간이 필요합니다. proc.wait(5)가 이 시간을 보장합니다.

브라우저 종료 (driver.quit)

녹화 완료 후 driver.quit()을 호출합니다. ChromeDriver에 세션 종료 HTTP 요청을 보내고, ChromeDriver는 Chrome 창을 닫습니다. finally 블록에 있어 예외 상황에도 반드시 실행됩니다.

정상 완료 출력 예시

[record] 브라우저 열기: https://…
{"physical_rect": {"x": 32, "y": 488,
 "width": 1746, "height": 982},
 "scale": 2.0, "dom_rect": …}
[recorder] 녹화 중... Ctrl+C를 누르세요
          → screen_captures/output.mp4
[recorder] 녹화 종료 신호 수신.
[recorder] 저장 완료: output.mp4

문제 발생 시 체크리스트

검은 화면 → 화면 기록 권한 없음
파일 크기 0 → setpgrp 없어 강제 종료됨
탐지 실패 → --dry-run으로 확인 후 --region 사용
좌표 틀림 → --scale 2.0 또는 1.0 명시

브라우저 제어 핵심

  • Python → HTTP → ChromeDriver → CDP → Chrome 4단계
  • element.rect = getBoundingClientRect via CDP
  • #movie_player 우선 탐지 (video 태그 y=-390 회피)
  • 3초 추가 대기로 SPA 동적 렌더링 보장

좌표 변환 핵심

  • 뷰포트 CS → 화면 CS → 물리 픽셀 CS 3단계
  • screenY + chrome_h + dom_y = screen_y (논리 px)
  • screen_y × devicePixelRatio = phys_y
  • screencapture에는 논리 px로 역변환해 전달

녹화·종료 핵심

  • stdin=PIPE로 EOF 종료 방지
  • setpgrp으로 SIGINT 격리, 파일 손상 방지
  • stdin "q" 쓰기로 정상 종료
  • finally 블록으로 항상 저장 보장
